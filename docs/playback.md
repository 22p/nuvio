# 播放与转码

播放决策只有一个原则：**能直连就直连，不能直连就尽量只换容器，最后才重新编码。**

## 三种播放方式

| 方式 | 何时使用 | 代价 |
| --- | --- | --- |
| 直连（Direct Play） | 客户端声明的容器与音视频编码都支持，码率不超过上限 | 无，直接读原文件 |
| 转封装（Remux） | 容器不支持，但视频编码能放进 fMP4，音频可复制或只需转 AAC | 几乎不耗 CPU，画质无损 |
| 转码（Transcode） | 编码或码率不兼容 | CPU / GPU 开销最大 |

没有 ffmpeg、关闭了转码/转封装，或者账号没有对应权限时，服务器会退回让客户端直连；能不能播由客户端自己决定。

## 直连

判定条件：

- 客户端没有提供设备档案 → 允许直连，让客户端自己试
- 提供了 `DirectPlayProfiles` → 容器、视频编码、音频编码都必须匹配
- 请求的码率超过客户端上限的 110% → 不直连
- 请求非默认音轨（音轨索引大于 1）→ 不直连，走转封装或转码

直连地址：

```
/Videos/{id}/stream?static=true&mediaSourceId=...
```

这个地址支持 HTTP Range，但必须携带有效的 `api_key` 或 `X-Emby-Token`；`DirectStreamUrl` 已经带好 token。第三方客户端如果把裸 URL 交给不支持附加请求头的播放器，直连会返回 401。

## 转封装

满足以下条件时使用：

- 视频编码是 H.264 / HEVC / AV1 / VP9（能装进 fMP4）
- 客户端声明支持该视频编码；没有设备档案时只假设 H.264
- 音频是 AAC、AC-3、E-AC-3、FLAC、Opus 且客户端声明支持，或直接转成 AAC

MP3 和 Vorbis **不会**复制：fMP4 封装器能写，但 MSE / Safari 放不出来，所以只把音频转成 AAC，视频始终不重编码。

输出是分片 MP4（fMP4）HLS。转封装从关键帧开始复制，因此会话总是从文件开头生成，播放器加载后自己 seek 到续播位置；缓存大小约等于片源大小。

## 转码

输出编码可选：

```
h264（默认，兼容性最好）
hevc
av1
vp9
```

所有输出都封装为 fMP4 HLS。HEVC / AV1 / VP9 需要客户端支持对应编码，不确定时用 H.264。

编码器选择：

- H.264 软件回退顺序：`libx264` → `libopenh264` → `h264_v4l2m2m`
- 其他编码使用对应的软件编码器
- 选择硬件加速且该后端支持目标编码时使用硬件编码器

硬件加速：

| 设置 | 后端 |
| --- | --- |
| Auto | 启动时探测 VAAPI / QSV / Vulkan，选择第一个有可用编码器的后端 |
| VAAPI | Intel / AMD，经 `/dev/dri` |
| QSV | Intel Quick Sync |
| Vulkan | Intel / AMD / NVIDIA，编码 H.264 / HEVC / AV1；VP9 只能解码 |
| Off | 仅软件 |

启动时会实际编码/解码一帧来验证，而不是只看设备节点是否存在。日志会打印类似：

```text
Hardware acceleration: vaapi (/dev/dri/renderD128) encode h264, hevc, av1 / decode h264, hevc, av1, vp9
Hardware acceleration: vulkan (0) encode h264, hevc, av1 / decode h264, hevc, av1
```

硬件初始化失败、或某个文件无法硬解时，自动回退软件编码。Vulkan 使用物理设备索引（`vk:0`），不是渲染节点路径；编码器支持取决于 FFmpeg 构建和驱动。

## HLS 会话与缓存

- 会话目录：`data/transcode/<会话ID>/`
- 90 秒内没有播放列表或分片请求 → 自动停止 ffmpeg；客户端再次请求时从上次分片继续
- 已暂停或 ffmpeg 已结束的会话超过 3 小时会被清理（持续有请求的会话不受这个时间限制）
- 同时最多 6 个活动会话，单个账号最多 3 个；超出返回 `429`，避免一个账号启动无限个 ffmpeg 进程
- 输出宽度上限 7680，超出会退回按高度推导
- 服务重启会清理转码目录
- 两个用户看同一集、参数相同时，目前仍各自生成一份会话；缓存不共享

## Web 播放器

- 直连 / 转封装 / 转码由服务端在 `PlaybackInfo` 中决定，播放器按返回的地址播放
- 支持音轨切换、字幕、0.5×–2× 倍速
- 实时信息面板显示源/输出分辨率、编解码器、帧率、码率、缓冲、丢帧、HLS 档位和会话
- 字幕是独立请求，不会触发视频重新编码

## 配置

设置 → 服务器：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 允许转码 | 开 | 关闭后不启动转码 ffmpeg |
| 允许转封装 | 开 | 关闭后容器不兼容时只能直连或转码 |
| 硬件加速 | Auto | Auto / VAAPI / QSV / Vulkan / Off |
| 视频编码 | h264 | 转码输出编码 |
| 默认码率 | 20 Mbps | 客户端没有指定时的上限 |
| 编码预设 | veryfast | `ultrafast` 到 `slow` |
| ffmpeg / ffprobe 路径 | 自动检测 | 留空则查 PATH |

每个账号还可以单独关闭转码或转封装；关闭后服务器不会为该账号启动对应的 ffmpeg 任务。

## 常见问题

**浏览器一直转圈**

先看是不是直连成功。MKV 里的 H.264 + AAC 通常会转封装，启动需要一点时间；如果片源是 HEVC 且客户端不支持，会转码。检查日志里是否有 ffmpeg 错误。

**播放很卡、CPU 占满**

可能是转码而不是转封装。查看播放器信息面板的「输出编码」；如果是软件转码，考虑开启 VAAPI / QSV / Vulkan，或把默认码率调低。

**没有声音**

常见于音轨索引切换：非默认音轨会触发转封装/转码。检查客户端是否声明支持该音频编码；不支持时会转成 AAC。

**关闭播放器后 ffmpeg 还在跑**

正常会在 90 秒空闲后停止；刚关闭时可能还在收尾。超过两分钟仍在运行，检查是否有其他客户端在拉同一会话。

**缓存盘被写满**

转封装缓存可能接近片源大小。把 `data/transcode` 放到独立磁盘或 tmpfs；注意 tmpfs 对高码率单集可能不够。当前没有总容量配额，需要外部清理或磁盘配额。
